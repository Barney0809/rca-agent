# 零成本重放：原始证据（#53 / D19）

> 这份文件存在的理由本身就是一条缺陷：**证明曾经只在我这台机器上**。
> `.gitignore` 里那条 `*.log` 把「21 次尝试、20 秒、毒化环境零网络」的原始输出
> 一起挡在了仓库外 —— 和 #38（"由存档生成"只在我机器上成立）同一族。
> 这里放一份**小的、能自己核对的**摘录；完整日志 `runs/_replay_full.log` 仍不进仓库。

## 一、结论（一句话）

在**任何真实 API 调用都必然失败**的环境下，7 场景 × 3 轮 = **21 次尝试全部命中录制并跑完**，
所以"回放不调 API"是**实测**的，不是从代码推出来的。

## 二、怎么复现（两条命令）

```powershell
# 1) 用你自己的 runs/ 打一个便携包（需要场景目录 + 录制都在场）
.\.venv\Scripts\python.exe scripts\make_replay_pack.py --faults F1 F3 F4 F5 F6 F7 F8 --out runs\_replay_pack

# 2) 把 API 变哑：假 Key + 指向一个无人监听的端口
$env:DEEPSEEK_API_KEY  = "sk-POISONED-replay-only"
$env:DEEPSEEK_BASE_URL = "http://127.0.0.1:9"
$env:RCA_REPLAY_ROOT   = "runs\_replay_pack"
.\.venv\Scripts\python.exe eval\runner.py --agent multi --rounds 3 --mode replay
```

毒化是**关键设计**：`run()` 会在开始前调 `check_replay_root_mode()` 与
`verify_replay_pack()`，replay 未命中即抛错，所以这条路径上**不存在**"偷偷退回真实调用"；
而只要发生过一次真实 HTTP，`127.0.0.1:9` 会立刻拒绝 ⇒ 跑完 = 没走过网络。

`pack.json` 里每个文件都有 sha256；`verify_replay_pack()` 在跑之前逐个核对，
**包被改过或少了文件都会在开跑前报错拒绝**（而不是跑到一半 miss）。

## 六、随仓库提交的演示包（D20b）

上面那次是 7 场景的完整包（4.4 MB，只在本机）。为了让**陌生人克隆后真能跑**，
另打了一个演示包并提交进仓库 —— `replay_pack/`（**1.73 MB**，F1+F8 两个场景，
录制裁剪 643 → 253 条）：

```
exit=0  wall=2s
  [F1 第1轮] ✅ 步数=30 工具=139 成本=¥0.0819 0.0s
  [F8 第1轮] ✅ 步数=33 工具=106 成本=¥0.0810 0.0s
  F8 第1轮   结论：外部风控变慢✅ 内存泄漏✅
```

两条附带验证：

- **篡改会被挡在开跑前**：把包里某一个 `.gz` 改一个字节，回放立刻报
  「重放包已损坏，拒绝在它上面跑」并列出不一致的文件与两个哈希。
- **打包是确定性的**：篡改后重新打包，`verify_replay_pack()` 直接通过 ——
  说明 gzip 字节可复现（`mtime=0`）。

`tests/test_replay_pack.py` 里有一条**真的重放一次**的用例
（毒化环境 + 跑完 F1），所以"零 API 调用"这句话每次跑 CI 都被重新证明一遍，
而不是只留在这份文档里。

## 七、边界（必须和结论一起读）

| 边界 | 事实 |
|---|---|
| 回放 ≠ 复现某一次归档运行 | 同一批响应：归档 `multi-20260925-131953` 判 **19/21**，回放判 **21/21**；21 次里 **13 次步骤数不同**（例如 F1 第2轮 **27→30**、F5 第3轮 **30→26**、F8 第2轮 **25→33** —— 左=归档、右=回放），F4 第 1、3 轮判定翻转（❌→✅） |
| 数字方向写反过一次（我自己抓到的） | 上面这几个例子第一次写成了 `F1 第2轮 30→27`（方向反了），是把乱码输出里的 `a/b` 当成 `b/a` 读的。`git log` 里 `46ce02a` 的**提交信息**还写着"21 次里有一半步骤数不同"（实测是 **13/21**）—— 提交历史按第 0 条规定不做改写，所以更正留在这里 |
| 第一个解释是错的 | 怀疑"同一 key 被后来的运行覆盖" —— **实测否定**：643 个 key，**0 个重复**。真原因是录制里混了 **4 次 record 运行**的响应，回放只能挑到"录制内部自洽的那条轨迹" |
| 包本体未入库 | 约 4.4 MB，见 `docs/00-状态.md` 的开放项；干净克隆里 `test_local_replay_pack_is_intact_if_present` 只会 **skip**（名字里的 local 就是为了说清这件事） |
| 未做 | "一批录制 = 一次运行"（做到之后回放才能对齐归档数字）；重放包的变异组覆盖的是**机制不变式**（gz 等价 / 包自检 / 数据根 / 只读包只允许 replay / 回放不得冒充测量），不含"回放对齐归档" |
