## 〇、先记住开场那三句

1. **我做了什么**：一个能对一个自建的三服务系统做故障根因分析的多 Agent 系统，
   而且是**可复现**的 —— 别人克隆下来，零成本就能核对我说的每个数字。
2. **我最重要的发现是个负结果**：多 Agent 没有可测的价值增量 ——
   4.3× 成本、3.5× 步数，而且准确率**还低 9.5 个百分点**（同样的 7 个场景、同样的样本数）。
3. **我为什么觉得它值得讲**：这个过程里我有**八次**得到过相反的结论，
   而每一次查下去都发现是**尺子**坏了（评分口径、题目真值、任务定义、计价模型……）。
   所以我把"**测量本身可信**"做成了工程机制，而不是靠自觉。

> 💡 三句话里，第 3 句是**最容易加分**的。绝大多数候选人讲的是"我做了个多 Agent 系统"，
> 而我能讲的是"我怎么知道我的结论不是幻觉"。

## 一、3 分钟版（电梯陈述）

> 我原来的技术栈是 Java，Python 是边做边学 —— 所以这个项目我刻意选了一个
> **"正确性可以被机械验证"** 的方向，而不是选一个"看起来厉害"的方向。
>
> 具体说：我搭了一个小的三服务系统（order → inventory → payment → 外部风控），
> 能注入 8 种故障；上面做了两条诊断路径 —— 单 Agent，和
> 三个专职 Agent（各自只看自己那一路遥测）加一个协调者做交叉质证与裁决。
>
> 结论是**多 Agent 更贵、更慢，而且没有换来任何准确率优势**：同一个世界、同一套评分、
> 同一个计价时段下，单 Agent 每次 ¥0.0172、准确率 100%；多 Agent 每次 ¥0.0732（**4.3×**），
> 准确率 **95.2%**（按当前判据；存档当时那版是 90.5%，见 #48）—— 步数从 8.3 涨到 28.8（3.5×）。
> 两侧覆盖的是**同样的 7 个场景 × 3 轮**，样本对等。
>
> 唯一的失败模式集中在 F4：协调者把真根因（一个反向的配置漂移）降级甚至驳回，
> 同时把一条**没有基线对比的"安静指标"**提升成了根因。
> 我一度怀疑这是评分口径冤枉了它 —— 读代码、对存档实测、再让第二把尺子逐条复核，
> **两把尺子完全一致：不是尺子问题。**
>
> **而且我没有把那个"低 9.5 个百分点"当作稳定结论**：它全部来自 F4 一个 n=3 的格子，
> 于是我又做了三次同预算配对实验 —— 方向一致（multi 一次都没超过 baseline），
> 但**幅度在 0 到 67 个百分点之间摆**，连 baseline 自己重跑都从 3/3 掉到 2/3。
> 所以我对外只说"**没有优势**"，不说"差多少"。
>
> 这件事我顺手做成了机制：运行器现在会在单场景样本 ≤3 轮时**自己打印**
> "只能看方向、不能比幅度"。
>
> 但更要紧的是**这个结论是怎么被保住的**：我一路上八次得到过相反的结论，
> 每一次都是"尺子"坏了 —— 比如有一道题的标准答案我写反了，
> 答对的反而被扣分；还有一次我把节假日按峰时计价，得出了假的"成本翻倍"。
> 所以我把工程重点放在"测量可信"上：关键词主判 + LLM 裁判交叉校验、
> 场景真值必须用对照实验验证、以及一份**错误封堵清单** ——
> 规则是：**一条错误只有在回归用例能变红之后，才算封堵**（用变异测试证明）。
>
> 我很清楚这个结论的边界：两侧覆盖同样的 7 个场景，但每侧只有 **3 轮**
> （轮间波动 ±7 个百分点），而且只测了一个模型。
> 所以我说的是"**在这 7 个场景、这个模型上没有优势，反而更差**"，不是"多 Agent 没用"。

## 二、10 分钟版（主线，按这个顺序讲）

### 1. 问题（1 分钟）

Agent 做 RCA 的真实难点不是"调模型"，而是：**模型的自述不可信**。
它会自信地给出一个错根因，也会在证据不足时编一个。
所以我的命题是：**用确定性机制同时约束它的判断和它的行动。**

### 2. 为什么"多 Agent 会更好"是不该直接信的（1 分钟）

单 Agent 的失败模式是**确认偏误**：先看到 CPU 飙升，后面所有证据都被它解释成"流量问题"。
多 Agent 看上去能治它（信息隔离 = 每个专员只看一路遥测；交叉质证 = 互相证伪）。
**但"看上去能治"和"测出来真有增量"是两件事** —— 这就是我要测的东西。

### 3. 我做了什么（2 分钟）

- **被诊断世界**：三个 FastAPI 服务 + Redis，8 种可注入故障，一条命令起全栈；
- **遥测**：文本日志 + Prometheus 指标，**先降维再进上下文**（原始遥测永不进上下文，压缩到 0.217%）；
- **两条诊断路径**：单 Agent；三个专员（工具面按角色隔离）+ 协调者（强制交叉举证：假设必须引用 `evidence_id`，机械校验，软约束做成硬约束）；
- **评测**：7 个场景 × 3 轮、噪声带、成本、收敛率，存档 + 轨迹全留。

### 4. 结果（2 分钟）

说数字，并且**主动说边界**（见 0 节和 `docs/06`）。
关键的一句：**两侧现在是同样的 7 个场景 × 3 轮**（样本对等），
多 Agent 的准确率是 **90.5%**，唯一的失败模式集中在 **F4**；
而 F4 的失败经过两把尺子逐条核对，**不是评分口径问题**。

### 5. 为什么我认为这个数字可信（2 分钟，这段是重点）

我能说出这台"尺子"是怎么校准的：

- **评分**：关键词/判据式主判 + LLM 裁判交叉校验（裁判不参与正确性计算，只作独立复核）。
  裁判先在 6 条人工标注样本上复现人工判定，再在 13 条对抗样本上验证
  （关键词版 0/13，裁判 13/13）；
- **题目真值**：每道题的"标准答案"必须用**绕开 LLM 的对照实验**验证 ——
  就是这一步查出 F2 那道题的答案是**反的**（只把连接池改小、下游完全健康，照样 851 个 5xx）；
- **成本**：按 token × 单价算，区分缓存命中/未命中，**并且处理法定节假日**（峰谷价差 2 倍）；
- **噪声**：噪声带按"轮"算而不是按"尝试"算（否则会把常数伪装成统计量）。

### 6. 工程机制（1 分钟）

**错误封堵清单**：每个错误记现象、根因、封堵措施、**以及一条能变红的回归用例**。
"能变红"由变异测试证明 —— 每个变异体会把缺陷重新注回一份代码副本，用例必须变红，
否则报 `NOT SEALED`。这套东西也被用来守它自己（防止变异体悄悄过期）。

### 7. 没做的部分（1 分钟，主动说）

架构设计里曾经有三条「未接线」，**现在都补上了**：
**MCP 收口**（ops 三工具经 MCP 暴露，6 条用例 + 2 个变异体）；
**LangGraph**（`StateGraph` + 官方 SQLite 检查点）；**断点续跑 AC-10**
（真杀进程 → 另一个进程续跑成功；4 条用例 + 2 个变异体）。
⚠️ 一处刻意的保留：**评测数字仍出自手写循环** —— 两侧必须同驱动才可比（ADR-0001 里写了这个取舍）。
README 里我专门留了一栏写这些，因为**把没做的写在首页，比被问出来强**。

## 三、40 分钟追问准备（Q → A → 证据在哪）

### A 组：关于"多 Agent 没用"这个结论

**Q1：你怎么确定不是你的多 Agent 实现太差？**
A：不能完全排除。我能做的是排除"结构性不公"：两侧同配置（同样的步数上限、同样的 JSON 催促）、
同时段计价、同一评分路径；并让多 Agent 在最该有优势的一端（F8 多故障）也被测到 ——
结论是它在那端也没有增量。剩下的解释是"实现不够好"，这是我认为**最可能的反驳**，
也是我下一步会测的方向。
> 证据：`docs/06` 定稿数字表 + 口径边界

**Q2：信息隔离真的做了吗？**
A：做了。三个专员各自只能看自己那一路（日志 / 指标 / 变更），工具面按角色限定，
有 18 条用例守着"专员看不到别人那一路"。
> 证据：`tests/test_agents.py`；`docs/00` D6

**Q3：交叉质证是不是形式主义？**
A：不是提示词里的一句话 —— 假设必须引用 `evidence_id`，协调者**机械地**执行举证责任：
没引用证据直接驳回；引用的证据全在支持自己、没有一条能证伪他人，也驳回。
> 证据：`src/rca/agents/coordinator.py`、`docs/03-事件流协议.md`

### B 组：关于"你怎么知道评分是对的"（这是最容易被追问的）

**Q4：关键词判定不是很脆吗？**
A：非常脆，而且我被它骗过**三次**（把"被否定的提及"算作命中 → 假阳性 100%；
否定语境被措辞绕过 → 又一次假阳性；判据合取却用析取判断"提没提过"）。
所以现在有两把尺子：关键词是主判据，LLM 裁判做独立交叉校验，两者不一致会被单独列出。
> 证据：harness-log #16 / #21 / #28

**Q5：那裁判自己错了怎么办？**
A：裁判不参与正确性计算，只做交叉校验；它先在人工标注样本上校准（6/6），
再过对抗样本（13/13，同批关键词 0/13）。
**而且我犯过一次"差点把裁判的错记进结论"的错** —— 后来发现是我自己的标注样本没检查，
于是给"凡标为 dismissed 的样本，其文本必须真的提到过那个原因"加了一条自动检查。
> 证据：`eval/judge.py --validate`、`--adversarial`；harness-log P8

**Q6：场景的"标准答案"是谁定的？**
A：我定的 —— 但**每一条都必须用绕开 LLM 的对照实验验证**。
`docs/04-故障目录.md` 里有一列就是"真值是否已验证"。目前 7 条有效场景里
F1/F3/F5/F6/F7/F8 已验证，F2 被证明**答案写反了**，已作废。
> 证据：`docs/04`、harness-log #20

### C 组：关于成本

**Q7：¥0.0172 是怎么算出来的？**
A：每次调用的 token 分别按缓存命中（¥0.02/M）、未命中（¥1/M）、输出（¥4/M）计，
再求和；峰时是谷时的 2 倍，**法定节假日全天按谷时**。两侧都在谷时。
> 证据：`pricing_tier` 字段随存档一起落盘；`scripts/cost_breakdown.py --run 1`

**Q8：你踩过什么成本的坑？**
A：三个，都很典型：
① 我把节假日按峰时算 → 得出假的"成本翻倍"，还写进了文档（这次是我自己抓到并更正的）；
② 我以为"给输出加上限"能省 23%，一测发现**截断了 JSON** → 那几次结论作废、收敛率归零，省的钱赔了有效性；
③ 我用"整文件统计"去比对，把两次运行混在一起，得出假的"输出 +77%"。
> 证据：harness-log #30/#31、#32、#33

**Q9：那你最后降本了吗？**
A：没有做成。测量结论是**输出占成本 72.3%**（缓存命中率 79.5% 已经很健康），
所以方向是"提示词层面要求结构化、更短"，但截断式的做法已被实测否决。
这件事我如实记成"未做"，而不是把一次失败的尝试说成成果。
> 证据：`docs/00` D11 小节

### D 组：关于工程素养（他们真正在看的）

**Q10：你怎么保证"改完真的修好了"？**
A：一条错误只有在**回归用例能变红**之后才算封堵 —— 用变异测试证明：
把缺陷重新注回一份代码副本，用例必须变红，否则报 `NOT SEALED`。
而且有元检查防止"变异体悄悄过期"（源码重构后查找串失配、用例却仍在绿）。
> 证据：`scripts/mutate_check.py`、`seal_report.py`

**Q11：你最严重的错误是什么？**
A：**我误删过一个工作目录之外的文档目录，且不可恢复**。
它带来的改变比这个项目本身更根本：此后所有删除走隔离区（软删除 + TTL + 可还原），
并且这个仓库有一条"不许删除"的规则（连临时目录都不许）。
> 证据：harness-log #1

**Q12：这个项目里你自己最不满意的地方？**
A：三处，且都不藏着：① 架构设计里那三条「未接线」**已经全部补上**（MCP / LangGraph / 断点续跑），但**评测仍走手写循环**（刻意的，为了两侧可比），
README 曾经把设计画成实现（已改，并加了用例守着）；
② 多 Agent 只测了 3 轮、只测了一个模型，"更差"的幅度（9.5 个百分点）本身就带着 ±7 个百分点的轮间波动；
③ 有些缺陷的封堵是"靠人"（流程缺陷），我如实标成靠人，不假装机器证明过。

**Q13：如果重做一遍？**
A：顺序会改：**先建尺子，再跑分**。具体是先做场景真值验证 + 对照实验 + 两把尺子，
然后再动手做 Agent —— 我的前 1/3 时间基本都花在"发现之前测的是假的"上面。
另外我会把 replay 录制做全，让整个评测**零成本可重放**。

### E 组：关于技术栈（我的弱项）

**Q14：你是 Java 栈，为什么用 Python 做这个？**
A：因为 Agent 生态在 Python。我用工程纪律补经验差：
静态门禁（未定义名字/异步误用）、190+ 条用例、变异测试、文档与代码对账。
而且我可以说清一个 Java 视角的好处：**我先想的是"这个不变量怎么被守住"**，
而不是"这个框架怎么用"。

**Q15：LangGraph 你熟吗？**
A：**不敢说熟，因为这个项目里我没真用它** —— 编排是手写循环。
我读过它的状态机/checkpointer 设计，也解释了为什么这个任务里手写循环够用，
但"没做过"和"做过"我不会混着说。如果岗位需要，我愿意在这上面补。
> ⚠️ 这一答很关键：**宁可承认没做，也不要顺着对方的话吹**。

## 四、讲述时的三条纪律

1. **任何数字都要能立刻说出"它从哪来、怎么复现"** —— 复现命令见 `docs/06` 的证据索引；
2. **主动说未做的部分**（比被问出来好得多，而且显得清楚边界）；
3. **不确定就说不确定** —— 例如"多 Agent 在其余五个场景未测"、
   "这套守卫是机制不是保证：任何守卫都可能被绕过"。

> ⚠️ 最后一条是这个项目最想表达的东西：
> **我不承诺"AI 不犯错"，我交付的是"错误会留下痕迹、并且能被机械地发现"。**
