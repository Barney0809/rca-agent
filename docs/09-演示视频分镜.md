# 09 · 演示视频分镜（**照着敲就行**）

> ## 这份文档的唯一职责
>
> **把"录一段 4–5 分钟的视频"变成一件不需要临场思考的事。**
>
> 视频本身要你自己录屏（我做不到）；这里给的是**分镜、命令、台词、预期输出**，
> 以及每一段的**翻车点** —— 那些我实际踩过、你一紧张就会踩到的地方。
>
> 数字一律不在本文里写死（见 [`docs/00-状态.md`](00-状态.md) 与 [`docs/06`](06-多Agent结果.md)）；
> 台词里要报数字时，**照着屏幕上的输出念**。

---

## 〇、录之前（5 分钟准备，能省掉一次重录）

| 检查 | 命令 | 为什么 |
|---|---|---|
| 世界在跑 | `docker compose ps` | 三个服务要 `healthy`；没起就 `make world-up` |
| 世界是干净的 | `.\.venv\Scripts\python.exe scripts\inject_fault.py status` | 参数应全是默认值（`pool_limit 64 / slow_op_ms 0 / risk_latency_ms 30`） |
| 终端 UTF-8 | `chcp 65001` | 否则中文输出是乱码，录进去很难看 |
| 字号 | 终端 16–18pt、窗口 ~100 列 | 1080p 下能看清，又不至于一行折两次 |
| **别露 key** | `echo $env:DEEPSEEK_API_KEY` 不要敲 | 录屏里出现 key = 必须重录 |
| 干净的工作树 | `git status --short` | 应当**空**；这段本身也是第 2 幕的证据 |

> ⚠️ 提前跑一遍全部命令（哪怕只是 `--help`），确认没有"第一次跑要下载/编译"的意外。

## 一、分镜（总长约 4 分 40 秒）

### 幕 1 · 0:00–0:25　一句话结论

- **画面**：浏览器打开 `demo/rca-demo.html`（双击即可，无需服务器）。
- **台词**：

  > 这是一个多 Agent 故障根因分析的实验。结论是负的：多 Agent 更贵、更慢，
  > 而且**没有换来任何准确率优势**。这一页不是截图 —— 它由存档生成，我接下来会证明这一点。

- **翻车点**：别急着讲机制，先把"负结论"说出来 —— 它才是这个项目最值钱的部分。
- **⚠️ 被追问"到底差多少"时**：页面上那个 4.8 个百分点来自**每侧只有 3 轮**的样本，
  而轮间波动是 **±7 个百分点** ⇒ 只能说「**没有优势**」，**不要说「确实更差」**。
  （这正是本项目反复栽的地方：把小样本的幅度当结论。见 `docs/06` 的口径说明。）

### 幕 2 · 0:25–1:05　页面**由存档生成**（可复现）

- **命令**：

      .\.venv\Scripts\python.exe scripts\make_demo.py
      git status --short

- **预期**：生成器打印"baseline 取：…（21 次尝试）/ multi 取：…（21 次尝试）"，
  然后 `git status` **什么都不输出**。
- **台词**：

  > 重跑生成器，页面逐字节一致 —— 所以 `git` 认为没有任何改动。
  > 存档随仓库提交，任何人零成本都能重放这一页。

- **翻车点**：如果 `git status` 出现改动，**停下重录**（那说明页面和存档不一致，
  这种情况本身有一条用例在守，详见 `tests/test_deliverable.py`）。

### 幕 3 · 1:05–1:50　数字的出处（**不花钱核对**）

- **命令**：

      .\.venv\Scripts\python.exe scripts\cost_breakdown.py runs\_recordings\record-deepseek-flash.ndjson --list
      .\.venv\Scripts\python.exe scripts\cost_breakdown.py runs\_recordings\record-deepseek-flash.ndjson --run 1

- **预期**：`--list` 列出文件里累积的多次运行（**现在是 24 次**）；
  `--run 1` 给出命中率 **79.5%**、**输出那一项占 72.3%**。
  ⚠️ 屏幕上会出现**两个钱数**：输出项 **¥0.0586**、**合计 ¥0.0810** —— 念的时候必须说清是哪一个。
- **台词**：

  > 文档里"输出占成本 72%"这个数，就是这一条命令跑出来的（屏幕上的 ¥0.0586 是**输出那一项**，
  > 合计是 ¥0.0810 —— 别把两个数念混了）。
  > 为什么必须指名 `--run 1`：录制是**追加**写入的，不指定就会取到别的那一次 ——
  > 我为此专门加过这个开关，因为文档引用的数字当时**复现不出来**。

- **翻车点**：这条命令的输出是"证据索引"的一部分（见 `docs/06` 的证据索引表）。

### 幕 4 · 1:50–2:45　"一条错误只有在用例能变红之后才算封堵"

- **命令**：

      powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ci.ps1
      .\.venv\Scripts\python.exe scripts\mutate_check.py --group ops_tools_deny_first

- **预期**：`make ci` 末行 `GATE PASSED`；变异检查打印
  `[OK] SEALED -- tests went red`，最后 `VERDICT: every mutant turned the tests red`。
- **台词**：

  > 这个项目对错误的纪律是：**只有回归用例能变红，才算封堵**。
  > 怎么证明"能变红"？把缺陷重新注回一份代码副本，用例必须变红 ——
  > 否则报 `NOT SEALED`。刚才那三个变异体都是"把门装回去"的尝试。

- **翻车点**：⚠️ **本机没有 `make`**（所以上面写的是 `powershell -File scripts\ci.ps1`，
  它和 `make ci` 跑的是同一个脚本）；`ci.ps1` 会跑一遍完整测试（实测 **约 2 分钟**）——**别剪掉**，
  让它完整播完，"门禁是常开的"这件事才有说服力。

### 幕 5 · 2:45–3:35　行动面：默认拒绝（`ops` CLI）

- **命令**（**注意顺序**，先演示拒绝）：

      .\.venv\Scripts\python.exe scripts\ops.py delete runs\_ops_demo\note.txt
      .\.venv\Scripts\python.exe scripts\ops.py grant --verb delete --path runs/_ops_demo
      .\.venv\Scripts\python.exe scripts\ops.py delete runs\_ops_demo\note.txt --grant-id <上一步的 id>
      .\.venv\Scripts\python.exe scripts\ops.py quarantine
      .\.venv\Scripts\python.exe scripts\ops.py restore <隔离区 id>

- **预期**（2026-09-27 **彩排实测**过一遍，逐字如下）：第一次是
  `⛔ 「删除」属于不可逆操作，默认拒绝（未提供授权）`；
  授权后是 `已签发授权：g-xxxxxxxx`（记下这个 id）；
  带 `--grant-id` 再删是 `✅ 已移入隔离区（不是删除，可还原）：q-…`；
  `quarantine` 列表的表头是 **`隔离区里有 N 条记录：待处理 M 项，已还原 K 条（保留记录，不会消失）`**
  —— ⚠️ **列表会带出历史条目**（我彩排后这台机器上有 4 条），念的时候按表头念"待处理 M 项"，
  别说成"隔离区里有 N 项待处理"；最后 `restore` 打印 `✅ 已从隔离区还原到 …`，
  文件内容**逐字节不变**。
- **台词**：

  > 删除在这套系统里**不是删除**，是移入隔离区 —— 因为"不可逆"这件事本身就不该存在。
  > 而授权只能由**人**通过这条 CLI 发：Agent 的工具面里**没有** grant 这个能力，
  > 否则"默认拒绝"就只是句口号。

- **翻车点**：`runs/_ops_demo/note.txt` 要先存在（现场 `New-Item`/`Set-Content` 造一个，
  或提前造好）；授权有 TTL（默认 300 秒），**别在两幕之间停太久**。

### 幕 6 · 3:35–4:20　诚实清单（**这段是加分项，别删**）

- **画面**：`demo/rca-demo.html` 第四节（诚实清单）+ `docs/harness-log.md` 的 F4 那几条。
- **台词**：

  > 我把自己的错误逐条列出来：作废的题目、被推翻的结论、口径边界。
  > 比如唯一失败的那个场景，我一开始怀疑是**评分口径冤枉了它** ——
  > 读代码、对存档实测、再让第二个尺子逐条复核，**结果是我错了，它真的更差**。
  > 后来还发现判据漏了英文词形，修正之后数字又变了 —— 这些都在日志里。

- **翻车点**：**不要**跳过这段。一个把自己的错误摊开的项目，比只报喜的可信得多。

### 幕 7 · 4:20–4:40　收尾：一句边界

- **台词**：

  > 三条边界：多 Agent 现在覆盖同样 7 个场景、每侧只有 3 轮，轮间波动 ±7 个百分点；
  > 只测了一个便宜模型；被诊断的系统是我自建的、故障是注入的。
  > 我交付的是**机制**，不是**保证** —— 任何守卫都可能被绕过。

## 二、录制时的四条纪律

1. **数字只念屏幕上出现过的** —— 不要凭记忆报数（这正是本项目栽过七次的地方）。
2. **主动说没做的**：LangGraph / MCP 收口 / 断点续跑都写在 README 的「未接线」表里，
   讲得越早越像"清楚边界"，被问出来才讲像"藏了东西"。
3. **不确定就说不确定**（例如"这一格只有 3 次尝试，幅度不稳"）。
4. **一个镜头一件事**：宁可多剪几段，也不要在一次连续录制里塞三件事（出错就得全重录）。
