# ADR-0002：两把尺子 —— 关键词主判 + LLM 裁判**独立**交叉校验

- **日期**：2026-09-25（D15 补记；实现于 D10）
- **状态**：已采纳
- **背景**：本项目的评分口径**被措辞绕过三次**，每次都制造出假阳性 100%：

  | 编号 | 现场 | 后果 |
  |---|---|---|
  | #16 | 「**只是** X，**并非**根因」这类否定表述被算成"主张了 X" | 多 Agent 的红鲱鱼失败被记成 100% |
  | #21 | 同上，换了个说法（"而非""脆弱点"）又漏了 | 又一次假阳性 100% |
  | #28 | 词表第三次被绕过；且判据是**合取**却用**析取**判断"提没提过" | 又是假阳性 |

  ⇒ 三次都是同一个机制：**我写词表 + 只有一把尺子**。词表天然追不上措辞的多样性。

---

## 决定 1：关键词/判据式判定是**主判据**，`correct` 只由它决定

**决定**：`correct`（准确率）**只**由关键词判定给出。

**理由**：

1. **可机械复现**：存档 → `eval/rescore.py` 离线重算，**不花钱、不需要网络**、
   任何人对同一份存档算出同一个数（FR-C 可复现的直接要求）；
2. **可审计**：判错的每一条都能指出"哪个关键词/哪条判据没满足"；
3. 如果让 LLM 直接决定正确性，结论会随**模型版本**漂移，历史存档就再也算不出同一个数。

---

## 决定 2：LLM 裁判接入，但**不参与**正确性计算

**决定**：裁判逐条对同一份文本给三分类判定（`asserted` / `dismissed` / `absent`），
与关键词判定**并列输出**；两者不一致的样本**单独列出、由人读原文判谁对**。
裁判**不参与** `correct`、也不参与聚合数字。

**理由**：

1. 词表追不上措辞，就需要一个**不依赖我词表**的独立视角 —— 这是唯一能跳出
   "用旧尺子校准新尺子"陷阱的办法；
2. 但它**不能**当主判据：一个不可离线复算的判据会让整个"可复现"主张失效；
3. "一致率高 ≠ 对" —— 两把尺子可能**一起错**（#16 就是这么活了很久的），
   所以分歧必须人工看，且**不许拿关键词当标准答案**（那还是用旧尺子校准）。

---

## 决定 3：裁判上线前必须先量两件事（而不是"上了就算成绩"）

**决定**：先校准再接线，两步都必须有数据：

| 问题 | 做法 | 实测结果 |
|---|---|---|
| 同一输入判多次，结论一样吗？ | 6 条人工标注样本，各判 3 次 | 6/6 复现人工判定；自一致性 8/8 |
| 它是否能挡住"我觉得能挡住"的攻击？ | 13 条**对抗样本**（专为绕过词表设计） | 裁判 **13/13**；同一批关键词 **0/13** |

**理由**：`temperature=0` **不等于**逐字可复现 —— 这件事必须实测，不能假设。
（工具：`eval/judge.py --validate` / `--adversarial`、`eval/judge_audit.py`。）

**代价**：

- 两套口径都要维护，且**标签表只能有一份**（harness-log **#43**：我曾在审计脚本里
  抄了一份，而那份表的注释恰好写着"各自写一份的话，两边迟早走散"）；
- 裁判有少量成本（每条约 ¥0.001 量级）；
- **对抗样本是我自己写的，且刻意针对我自己的标记表** ⇒ 它能证明"词表会被绕过"，
  **不能**证明"裁判扛得住任意真实语言"。这条边界写在 `docs/00` 的待办里。
