# ADR-0005：F2 作废（保留为反例），而不是"把它修好"

- **日期**：2026-09-25（D15 补记；决定发生在 D7.5）
- **状态**：已采纳
- **背景**：D7 第一次跑多 Agent 时，F2 上它"答错了"（分数很低）。
  按当时的判断，这足以否定"多 Agent 有价值"这个命题。
  但在下结论之前，我用**绕开 LLM 的对照实验**问了一个物理问题：

  > 把连接池改小、下游完全健康时，事故会不会自己出现？

  实测（`scripts/exp_pool_vs_latency.py`，零 LLM 成本）：

  | 配置 | 池 | 风控延迟 | 5xx |
  |---|---|---|---|
  | "池小 + 风控慢"（F2 原设定） | 2 | 800ms | 1487（97%） |
  | **只把池改小、风控正常** | 2 | 30ms | **851** |
  | 池保持默认、风控慢 | 64 | 800ms | **0** |

  **结论：池被改小本身就会造成事故** —— 而 F2 声明的标准答案是
  「外部风控变慢是根因、池耗尽是症状」，**恰好是反的**。

---

## 决定 1：把 F2 标为 `invalidated`，默认不跑、不参与聚合

**决定**：在场景定义里写 `invalidated_reason`；运行器遇到它**跳过并打印理由**；
聚合数字里排除它（`n_excluded_attempts` 单独记账）。

**理由**：

1. **错的是题目，不是模型**：它答的（池耗尽）才是对的。
   如果留着它参与评分，就是"把答对的扣分、把答错的加分"，比没有这道题更糟。
2. **不能偷偷改题**：直接改标准答案会让新旧数字混在一起、不可比。
   **作废 + 明确理由 + 保留为反例**，是对历史数字最负责的处理。
3. 一道题**在对照实验里说不清"谁移除后事故消失"，它就不该有标准答案**
   —— 这条已经上升为本项目的判据说纪律（#20）。

---

## 决定 2：红鲱鱼职责交给 **F7**（重新设计，不是改 F2）

**决定**：新增 F7 = "无关变更干扰"（变更记录里有一条与事故**因果无关**的变更，
且真根因不在变更记录里），F1 作为它的对照。

**理由**：F2 原本想考的能力是"有变更 ≠ 是它"。
但它的实现让"那条变更就是真根因"，所以它考的是**反过来的东西**。
把职责交给新设计的场景，比修补旧场景干净 —— 旧场景的失败模式已经污染了历史预期。

---

## 代价与残留

- 少一道题（有效场景 7 个而不是 8 个）；
- 需要**机制**守住"作废场景不会被顺手跑进来"：`--include-invalidated` 显式开关 + 用例
  （变异组 `invalidated_scenario_exclusion` 背书）；
- 更重要的残留：**这条教训逼出了一个跨场景的纪律** —— 此后每个场景的真值都必须用
  对照实验验一遍（实测结果见 `docs/04-故障目录.md` 的「二之补」），
  F4 也因此被重新审视为"歧义"而不是"反转"。
