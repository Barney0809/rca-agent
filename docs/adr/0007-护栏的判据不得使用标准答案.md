# ADR-0007：护栏的判据**不得使用标准答案**（以及"拦"这件事不交给 LLM）

- **日期**：2026-09-25（D21）
- **状态**：已采纳（M1 尚未实现；**本文档先冻结判据边界**，避免实现阶段走偏）
- **背景**：项目要加一个**护栏** —— 在 Agent 运行时看着它、必要时提醒或拦截。
  最省事的做法是复用现成的评分器：它已经知道标准答案，判"这条结论对不对"非常准。

  **但那样做出来的不是护栏，是第二个裁判。** 本 ADR 就是把这个诱惑明确否掉。

---

## 决定 1：护栏的判据**不得读取标准答案**

**决定**：护栏只允许使用"轨迹里有没有证据"这类**可自证**的性质：

- 某个数值是否出现在某次工具返回里；
- 某条原因主张是否有对应的工具调用与返回；
- 某个指标是否有基线/变化证据。

严禁 import `eval/scenarios.py` 的 `SCENARIOS`（标准答案）或任何由它派生的关键词表。

**理由**：真实环境里没有标准答案。一个偷看答案的护栏**只能在评测里工作**，
部署到真实系统上第一时间就失效 —— 那就不是护栏，只是又一个评分器。
这条同时把两个角色分开：**裁判在评分路径**（可以看答案），**护栏在运行路径**（绝不能）。

**代价**：表达力明显受限。护栏抓不到"结论方向反了""原因找错了"——那些判断依赖答案。
它只能抓**可自证的形式缺陷**。本 ADR 接受这个代价：
**宁可只抓三类硬的，也不做一个看起来全能、实则只在评测里成立的护栏。**

**落地约束**（要有守卫，不能只写在文档里）：

- `src/rca/guard/` **不许** import `eval.scenarios` —— 用 AST 扫 import 的结构性守卫；
- 回归用例里必须有一条"护栏看不见答案"的检查：把结论里的正确答案换成错的，
  护栏的判定**不该因此改变**（它只看证据，不看对错）。

---

## 决定 2：能"拦"的规则必须是确定性的；LLM 只能提醒，不能拦

**决定**：分两层。

- **硬层** = 确定性规则（纯函数 `Trace -> [Finding]`），可以 `deny`；
- **软层** = LLM 审查者，只能产出**提醒**，且只给主 Agent **一次**自我修正机会，
  其输出**不进 `correct` 判定**。

**理由**：用不可靠的 LLM 去拦不可靠的 LLM 是**循环论证** ——
本项目的前提就是"LLM 的自觉不可靠"（整个仓库的主题），
所以"拦住"这件事不能寄望于另一次 LLM 判断。
反过来，形式化规则能判的东西有限 ⇒ 剩下的交给软提醒：
把矛盾**指给主 Agent 看**，让它自己改，这比替它下判断安全。

**代价**：

- 硬规则会**误伤**（打转像深挖、谨慎像犹豫）⇒ 必须用"开关护栏"的对照实验**量化误伤**，
  而不是声称没有；
- 软提醒要花钱（粗估单次 +30% 成本）⇒ 必须测"增益是否值这个价"，
  **测出负结论就如实报**（本项目有先例：D11"给输出加上限"被实测否决）。

---

## 决定 3：对外接入形态用 **MCP 代理**，而不是要求对方改代码

**决定**：护栏对第三方 Agent 的接入方式是**中间层**：

```
外部 Agent  →  我们的 MCP 代理（审计 / 判定 / 必要时拦截）  →  真实工具
```

**理由**：三条路（读事件流 / 注册钩子 / 代理）里，只有代理**既能拦、又不要求对方改代码**；
而且本仓库已经有 `src/rca/mcp_server.py` 与 `src/rca/mcp_client.py`（D17 那套），
MCP 也是当前最通用的工具协议。对第三方的要求只剩一句"把工具接到这个代理上"。

**代价（必须写在明处）**：

- MCP 流量只覆盖**行动面**（工具调用与返回）。**判断面** —— 它最后那句结论 —— 不在流量里。
  所以判定"这个数字没依据"必须要求对方在结束时**回传结论**
  （一个 `submit_conclusion` 工具，或读它的 stdout）。**这个接口形状现在就要定下来**，
  否则后面所有规则都会卡在这里。
- 代理是**单点**：它挂了，对方的工具调用也就挂了。生产上要考虑可用性（本项目只做演示与验证）。
- 平台的**真实验证方式**不是"找个真外部 Agent"，而是**造一个已知会犯某类错的 Agent**
  （把已知错误注入进去当 ground truth）——否则护栏对不对**无法判定**。

---

## 决定 4：先跑在自家轨迹上（reference adapter），外部接入是第二步

**决定**：M1 的第一个适配器是**自家 multi 流程**；外部框架适配器排在 M2/M3。

**理由**：这是唯一能**测量**的顺序 ——

- 自家轨迹有标准答案 ⇒ 能测"护栏有没有误伤"；
- 自家轨迹有**已归档的真坏轨迹**（F4 那次：协调者把真根因降级、
  把**没有基线**的安静指标提升成根因 = harness-log #44）⇒
  能**零成本回放**证明"护栏会触发"。

外部 Agent 没有真值，先做它只能得到"看起来挺聪明"的演示，
得不到"它到底对不对"这个答案。

**代价**：短期内对外叙事弱一点（"先监控自己"）。
接受：**先有可测量的证据，再有平台故事。**

---

## 与其他决策的关系

- ADR-0002（两把尺子）：裁判与关键词评分器是**评分路径**的两个独立口径；
  护栏是第三条路，且**刻意不看答案** —— 三者不许互相污染（#16/#21 的教训）。
- ADR-0006（不存在硬删除）：护栏的 `deny` 只允许"不做什么"，
  需要"撤销什么"时一律走隔离区 + 可还原，不引入新的不可逆操作。

## 补记（2026-09-25，M1 实测）：决定 1 的边界被**测量**证实了

决定 1 原本是**推理**（"偷看答案的护栏没法部署"）。M1 做完之后它变成了**实测**：

我原本想让护栏抓 `#44` 那个真实缺陷（"无基线的绝对值指标被当成根因"），
于是写了旗舰规则 `unbased_metric`。21 次归档尝试的实测结果：

```
它确实抓到了 F4 的真缺陷（报出 stock_level）      ✅
但 19 个**正确**结论里它报了 14 个                  ❌
⇒ 精确率 1/15 ≈ 7%
```

正确结论也会点名"只有单个采样值的指标"（F8 的泄漏是真故障，只是指标只读到一个值）。
**区别这两种情况需要知道哪个原因才是真的 = 需要标准答案。**
⇒ 该规则降级为**诊断量**（不参与判定），细节见 `docs/harness-log.md` #55。

**这正好是决定 1 说的那个代价**：护栏的表达力是受限的，而"受限"不是含糊其辞，
是可以量出来的 —— 7%。承认它，比做一个看起来全能、实则靠答案的护栏要好。
