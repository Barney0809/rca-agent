# ADR-0003：三个专员按「遥测种类」分工，而不是按「服务」分工

- **日期**：2026-09-25（D15 补记；实现于 D6）
- **状态**：已采纳
- **背景**：多 Agent 最直觉的分法是"每个被诊断服务配一个 Agent"。本项目选了另一种：
  按**证据类型**分成三个专员 —— 日志 / 指标 / 变更记录（`src/rca/agents/roles.py`）。

---

## 决定 1：按遥测种类分工，每路只看自己那一路

**决定**：专员的边界画在**证据类型**上，不是画在服务上。

**理由**：

1. **按服务分会复制视角**：那三个 Agent 每个都要看日志 + 指标 + 变更 ——
   视角几乎完全重叠，隔离度极低，"多视角"退化成"同一份数据看三遍"。
2. **RCA 的真实分歧发生在证据类型之间**：日志说"在重试"、指标说"延迟高但自身耗时正常"、
   变更记录说"有人改过配置" —— 这三句话是**互相证伪**的关系。
   把边界画在这里，交叉举证才有内容可举。
3. **F7（合格红鲱鱼）就是为这条设计的**：变更记录里有一条与事故无关的变更，
   真根因只在指标里。若没有隔离，一个 Agent 会顺手把两件事都说了，
   而"变更 ≠ 根因"这个判断就被跳过了。

---

## 决定 2：隔离必须是**可测**的，不是口头约定

**决定**：`RestrictedToolBox` 按角色限制工具面，并有 18 条用例守着
"日志专员拿不到指标工具"这类断言。

**理由**：凡是"约束模型行为"的设计，如果不可测，就等于没有 ——
本项目对"自觉"的一贯态度就是"不许靠自觉"。

**代价**：专员看不到全局，必须由协调者整合；整合质量本身成为新的失败点（见 D7 的结论）。

---

## 决定 3：承认这套分工的**已知失效面**

**决定**：把分工的边界写进结论，而不是只讲优点。

- **本项目的测量结论是"多 Agent 没有价值增量"**（4.0× 成本、3.5× 步数、准确率不变）——
  也就是说：**这套分工设计在成本上明显更差，在准确率上没有换来好处**；
- 若某个故障只有**单一证据类型**能看出来（例如 F6 内存泄漏主要在指标里），
  分工不会带来任何增益，只是多花钱；
- 多 Agent 只在 **F1/F8** 两个场景上测过，"没有增量"**不能外推**到其余五个场景。
