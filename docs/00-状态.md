## 三、如何恢复工作

### 新会话 / 新代理的第一件事

```
1. 读  AGENTS.md                    ← 硬约束（禁止删除、编码纪律、用户背景）
2. 读  docs/00-状态.md              ← 本文件，进度与下一步
3. 读  docs/01-需求分析.md §2.3     ← 项目动机（含那次事故）
4. 跑  scripts/dev.ps1              ← 确认环境
5. 跑  scripts/smoke_world.py       ← 确认被诊断系统是活的
```

### 常用命令

```powershell
# 环境自检
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev.ps1

# 起被诊断系统（一条命令）
docker compose up -d --build

# 验证链路
python scripts/smoke_world.py        # 或 make smoke

# 看日志（按 trace 关联）
docker compose logs --no-log-prefix order inventory payment | Select-String '<trace_id>'

# 停（不删除容器）
docker compose stop
```

### 一次完整验证的最短路径

```powershell
cd D:\BarneyQ\Projects\rca-agent
docker compose up -d --build
python scripts/smoke_world.py
```

### ⚠️ 两条踩过的坑

1. **可执行脚本必须纯 ASCII**。PowerShell 5.1 会把 UTF-8 无 BOM 的脚本按 GBK 读，

## 七、更新纪律

**每完成一个里程碑，必须：**

1. 更新本文件的「一、当前进度」与「二、下一步」
2. 如有新决策 → 写一条 `docs/adr/`
3. 如有新封堵的错误 → 追加 `docs/harness-log.md`
4. `git commit`，并在提交信息里写上里程碑编号

**为什么这么严**：上下文会随对话变长而失真，但**文件不会**。
把状态写进文件，等于把"记忆"外置——新会话、新代理、甚至你自己一周后回来，
读三个文件就能接着干。
