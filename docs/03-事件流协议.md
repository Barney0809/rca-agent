# 事件流协议：rca-agent

> 状态：**D0 冻结**。CLI 与前端（L3）共用同一份协议。
> 本文只定义协议，不含实现。

---

## 0. 为什么要有这份协议

系统里有四样东西本来会各自长出一套日志：**CLI 输出、前端事件流、全链路 trace、策略审计**。

如果分开做，会出现四个问题：格式不一致、字段对不上、回放不了、前端后补要重写 Agent 层。

**所以合并成一套：一条 append-only 的事件流，同时是这四样东西的唯一事实来源。**

| 消费者 | 用法 |
|---|---|
| **CLI** | 按类型过滤后打印（开发期 90% 时间用它） |
| **前端（L3）** | 订阅全量，客户端过滤渲染 |
| **Trace（FR-5.1）** | 直接落库，不额外埋点 |
| **审计（FR-2.7）** | `policy.*` 事件即审计记录 |
| **回放（FR-5.2）** | 事件流本身就是可重放记录 |

---

## 1. 设计原则

| # | 原则 | 理由 |
|---|---|---|
| P1 | **单一只追加**（append-only） | 回放与审计的前提；事件不可修改 |
| P2 | **每个事件自包含** | 单独看一条也能理解，便于过滤与切片回放 |
| P3 | **稳定信封 + 可变 payload** | 消费者只依赖信封；新类型不破坏旧消费者 |
| P4 | **未知类型必须被忽略，不得报错** | 前向兼容；CLI 与 UI 都不认识新类型时照常跑 |
| P5 | **`trace_id` 显式传参** | **不用 ThreadLocal**——它在异步/线程池上会静默丢账串账 |
| P6 | **敏感字段可标记** | 开源与分享回放时按标记脱敏 |
| P7 | **真值延迟揭示** | 场景的真名不得提前进入事件流（见 §4.1） |

---

## 2. 信封（Envelope）

所有事件共享这一层。

```json
{
  "v": 1,
  "seq": 1234,
  "ts": "2026-09-23T22:01:03.123+08:00",
  "run_id": "r-20260923-0007",
  "trace_id": "t-8f3a1c",
  "span_id": "s-0042",
  "parent_span_id": "s-0031",
  "actor": { "kind": "agent", "name": "logs_agent" },
  "type": "agent.hypothesis",
  "data": { },
  "cost": null,
  "redact": []
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `v` | int | schema 版本，当前 `1` |
| `seq` | int | 单次 run 内单调递增，全局有序 |
| `ts` | string | RFC3339 带时区 |
| `run_id` | string | 一次诊断运行 |
| `trace_id` | string | **显式传递**，跨 Agent / 跨进程 |
| `span_id` | string | 当前步骤 |
| `parent_span_id` | string\|null | 用于重建调用树 |
| `actor` | object | `kind` ∈ `agent` / `coordinator` / `policy` / `llm` / `system` |
| `type` | string | 事件类型（§3） |
| `data` | object | 类型专属载荷 |
| `cost` | object\|null | 本次 LLM 调用的成本（§5） |
| `redact` | string[] | 需要脱敏的 `data` 路径（§8） |

## 3. 事件类型全表

### 3.1 run 生命周期

| type | data 关键字段 |
|---|---|
| `run.started` | `scenario_id`, `config_digest`, `model_routing`, `budget` |
| `run.finished` | `verdict`, `total_steps`, `total_cost`, `duration_ms` |
| `run.failed` | `reason`, `last_seq` |

### 3.2 场景（注意 §4.1 真值延迟）

| type | data 关键字段 | 说明 |
|---|---|---|
| `scenario.injected` | `acknowledged: true` | **不含故障名** |
| `scenario.revealed` | `fault_class`, `symptom_service`, `root_service`, `ground_truth` | **只在 `run.finished` 之后发**，供对账 |

### 3.3 Agent 步进

| type | data 关键字段 |
|---|---|
| `agent.step.started` | `step`, `objective` |
| `agent.thought` | `text`（可截断，见 §8） |
| `agent.tool.call` | `tool`, `args`, `call_id` |
| `agent.tool.result` | `call_id`, `ok`, `summary`, `latency_ms`, **`evidence_id`** |
| `agent.hypothesis` | `hypothesis_id`, `claim`, `confidence`, **`supports: [evidence_id]`** |
| `agent.step.finished` | `step`, `conclusion`, `stop_reason` |

### 3.4 Coordinator

| type | data 关键字段 |
|---|---|
| `coordinator.dispatch` | `targets`, `instruction` |
| `coordinator.conflict` | `between: [hypothesis_id]`, `nature` |
| `coordinator.rejected` | `hypothesis_id`, **`reason`**, **`required_evidence`** |
| `coordinator.verdict` | `root_cause`, `evidence_chain: [evidence_id]`, `confidence`, `dissent` |

> `coordinator.rejected.required_evidence` 是**整个演示里最有说服力的一屏**——它把"交叉举证"从口号变成可见的要求。

### 3.5 策略执行点 ★（项目独有）

| type | data 关键字段 |
|---|---|
| `policy.allowed` | `op`, `path`, `verb_level`, `grant_id` |
| `policy.denied` | `op`, `path`, `verb_level`, **`reason`**, **`suggestion`** |
| `policy.quarantined` | `path`, `quarantine_id`, `ttl_s` |
| `policy.restored` | `quarantine_id`, `path`, `ok` |

> **`policy.denied.suggestion` 必须给替代做法**，不能静默失败（FR-2.8）。

### 3.6 成本与预算

| type | data 关键字段 |
|---|---|
| `cost.accrued` | 见 §5（随信封的 `cost` 字段一并携带） |
| `budget.warning` | `dimension`, `used`, `limit` |
| `budget.exhausted` | `dimension`, `used`, `limit` |

### 3.7 护栏与系统

| type | data 关键字段 |
|---|---|
| `guard.tripped` | `layer` ∈ `max_rounds` / `token_budget` / `money_budget` / `no_progress`, `detail` |
| `log` | `level`, `msg` |
| `error` | `where`, `message`, `retriable` |

### 3.8 预留（不实现，但消费者必须忽略）

`agent.memory.*`、`eval.*`

## 4. 两个关键设计

### 4.1 真值延迟揭示——协议层面保证"可验证性"

演示时观众**不能提前知道注入了什么故障**，否则"系统推出来了"这句话就失去意义。

所以协议强制拆成两条：

- `scenario.injected` —— 只有 `acknowledged`，**不含任何故障信息**
- `scenario.revealed` —— 只在 `run.finished` **之后**发出，含 ground truth，用于对账展示

**这条约束写在协议里，而不是指望代码里记得别打印。** 约定靠不住，schema 靠得住。

### 4.2 证据 ID——让"交叉举证"可机器校验

`agent.tool.result` 产出 `evidence_id`，`agent.hypothesis` 必须引用它。

于是 Coordinator 可以**机械地**执行举证责任：

- 假设未引用任何证据 → 直接驳回
- 假设引用的证据全部**支持自己**、没有一条能证伪他人 → 驳回并要求补证

> 这一步把"强制交叉举证"从**提示词里的一句话**，变成**协议层面的硬约束**。
> 这正是本项目核心命题的体现：**不靠模型自觉，靠机制。**

## 5. 成本字段（使用 DeepSeek 真实字段名）

```json
"cost": {
  "model": "deepseek-flash",
  "thinking": false,
  "input_tokens": 1200,
  "output_tokens": 300,
  "prompt_cache_hit_tokens": 1000,
  "prompt_cache_miss_tokens": 200,
  "yuan": 0.0013
}
```

要点：
- 模型名取**响应里返回的**模型名，不是请求里写的（请求可能被路由改派，用请求名会算错账）
- `thinking` 必须记录——**它默认是开的**，不关就持续付推理 token 费，成本曲线会失真
- 单价从配置读，未配单价写 `null`，**不写 0**（0 是"免费"，null 是"未知"）

## 6. 传输

### 6.1 实时（SSE）

```
GET /events?run_id=r-20260923-0007
Content-Type: text/event-stream
```

- 每条事件 = 一个 SSE 事件，`data:` 后跟**单行** JSON（序列化时禁用换行、禁用缩进）
- 每 15 秒发一次心跳注释行，防中间层断连
- 断线重连：客户端带 `Last-Event-ID`，服务端从 `seq > last` 续发

### 6.2 回放（离线）

```
GET /runs/{run_id}/events        → application/x-ndjson
```

整个事件流按 `seq` 顺序返回。**这就是 FR-C.3「录制/回放」的载体**——访客无需 API Key 即可重放一次完整诊断。

---

## 7. 存储

| 位置 | 形式 | 用途 |
|---|---|---|
| `runs/{run_id}/events.ndjson` | 只追加 JSONL | 唯一事实来源、回放 |
| SQLite `events` 表 | 索引列：`run_id`,`seq`,`type`,`ts`,`actor` | 过滤查询、评测统计 |
| SQLite `evidence` 表 | `evidence_id` → 内容摘要 | 证据链校验 |

> JSONL 是主，SQLite 是索引。**丢了库可以从 JSONL 重建，反之不行。**

---

## 8. 脱敏

`agent.thought.text`、工具参数里的路径、prompt 片段可能含敏感内容。规则：

- 产生事件时标记 `redact: ["data.text", "data.args.path"]`
- 导出/分享/回放包时按标记替换为 `"<redacted>"`
- **本地运行不脱敏**（开发需要），**仅导出时生效**

回放包（`make share`）默认脱敏——这是 L3 和开源仓库能公开的前提。

---

## 9. 版本与兼容

| 规则 | 内容 |
|---|---|
| 升 `v` 的条件 | 信封字段被删除或语义变更 |
| 不升 `v` 的条件 | 新增事件类型、新增 `data` 字段 |
| 消费者义务 | **必须忽略未知 `type` 与未知字段，不得报错**（原则 P4） |
| 单一发射器 | 所有事件经同一个 `Emitter` 发出，`trace_id` 显式传入，**不用 ThreadLocal** |

## 10. 与验收标准的对应

| 验收标准 | 由协议直接支撑 |
|---|---|
| AC-5 越界删除 100% 被拒且可解释 | `policy.denied.{reason, suggestion}` |
| AC-7 隔离区可完整还原 | `policy.quarantined` / `policy.restored` |
| AC-8 每次拒绝均有审计，无静默失败 | `policy.*` 即审计；单一只追加 |
| AC-9 事故回归用例能变红 | 回归用例断言事件序列 |
| AC-10 断点续跑 | `seq` + `run_id` 可定位续跑点 |
| AC-13 L3 可触发可观看 | SSE 端点 |
| AC-14 决策可讲解 | 事件流本身即讲解素材 |
| FR-C.3 离线复跑 | NDJSON 回放端点 |
