# 护栏设计（M1–M4）

> **一句话定位：这不是第二个裁判。**
> 裁判判"结论对不对"（评分路径，**可以**看标准答案）；
> 护栏判"过程有没有形式缺陷"（运行路径，**绝不许**看答案 —— 见 ADR-0007）。
>
> 本文档只写**设计与验收形状**；进度、计数、完成状态一律看 `docs/00-状态.md`。

---

## 一、它解决什么问题

Agent 会犯错，但错误分两类，处置方式完全不同：

| 类别 | 例子（都来自本仓库真实归档） | 能不能确定性判定 |
|---|---|---|
| **形式缺陷** | 结论里的数值在工具返回里根本找不到（幻觉数字）；主张的原因没有任何工具证据；把**没有基线**的绝对值指标当根因（#44） | ✅ 能 —— 只需要"证据在不在" |
| **判断错误** | 原因选错了、方向反了 | ❌ 不能 —— 那需要标准答案 |

**护栏只做第一类。** 第二类交给评测（裁判 + 关键词两把尺子）与人。
这不是能力不足的妥协，而是**边界选择**：一旦越界，护栏就只能在有答案的环境里成立。

## 二、为什么第一个适配器必须是自家轨迹

平台化的目标是看住**外部 Agent**，但顺序不能反：

- 自家轨迹有**标准答案** ⇒ 能测出护栏**有没有误伤**（对外部 Agent 无真值，测不了）；
- 自家轨迹有**已归档的真坏轨迹**（F4/#44）⇒ 能**零成本回放**证明"护栏会触发"；
- 外部 Agent 的失败原因不属于我们 ⇒ 先做它只能得到"看起来挺聪明"的演示。

⇒ 顺序：**判定核心（纯函数）→ 自家 reference adapter → 外部 adapter**。

## 三、三层结构（越硬的判断越不交给 LLM）

| 层 | 谁来做 | 能做什么 | 判据来源 |
|---|---|---|---|
| **硬层** | 确定性规则（纯函数） | `allow` / `warn` / **`deny`** | 轨迹里的证据存在性 |
| **软层** | LLM 审查者（M2） | 只能**提醒**，一次自我修正机会 | 读同一份轨迹，**不进判分** |
| **留痕层** | 审计 | 每次干预写 `runs/_audit.ndjson`；可从归档 trace 复算失败类别 | 已有 |

硬层挂在**两个唯一出口**上，天然覆盖所有角色（D9 的经验：`ToolBox.call` 是所有工具调用的唯一出口）：

```
Agent ──> ToolBox.call ──(硬层事前判定)──> policy.authorize ──> 真实工具
                    │                              │
                    └────── 审计 + 事件流 ─────────┘
```

## 四、标准事件接口（这就是"平台"的接口形状）

接入任何框架，本质都是**把它翻译成这串事件**：

```python
ToolCallEvent(step:int, name:str, args:dict)                 # 它要调什么工具
ToolResultEvent(step:int, name:str, ok:bool, text:str)       # 工具回了什么（数值都在这里）
ClaimEvent(text:str)                                          # 它主张了什么（结论/中途断言）
FinalEvent(text:str, stop_reason:str)                         # 它最后交回来的东西
```

`Trace = list[Event]`。**判定核心只认这串事件**，不认任何框架类型。

⚠️ 两个接口要点（ADR-0007 决定 3 的落地）：

- **判断面必须回传**：MCP 代理只能看到工具调用与返回，看不到"它最后那句结论"。
  所以外部 Agent 必须调一次 `submit_conclusion(text)`（或由适配器读它的 stdout）；
- **允许缺证据的轨迹**：若对方只给了 `ToolResultEvent` 而没有 `ClaimEvent`，
  护栏应报"无法判定（缺少结论事件）"，**而不是默认放行** ——
  "没看见问题"与"没有问题"必须分开（同 #26 的空绿教训）。

## 五、M1 的三条规则（全部不依赖标准答案）

| 规则 | 判定 | 证据指针 | 为什么不需要答案 |
|---|---|---|---|
| `unverifiable_number` | 结论里的每个数值（含字段名/单位附近的数字）必须能在某次 `ToolResultEvent.text` 里找到 | `step` + 工具名 + 该值出现的原文片段 | 只需在**已被采集的数据**里查存在性 |
| `unsupported_claim` | 结论里的每条原因主张，必须至少有一条工具证据（返回里出现过相关词或字段） | `step` 列表 | 同上 |
| `unbased_metric` | 把某个**绝对值指标**当根因，而 trace 里没有该指标的基线快照或前后差异 | 指标名 + 缺失的基线类型 | #44 的真实缺陷就是"无基线"，判定依据是"有没有基线"，不是"对不对" |

三条都满足：**换成错的答案，判定不变**（这是决定 1 的回归检查）。

## 六、验收形状（**双侧**，缺一不可）

| 侧 | 用什么验 | 通过标准 |
|---|---|---|
| 必须触发 | 归档的 F4 坏轨迹（#44），**零成本回放** | 报出"无基线指标被当作根因"，并给出步骤与指标名 |
| 不许误伤 | 答对的轨迹（如 F1/F8 已归档的正确答案） | **零 Finding** |
| 每条规则 | 一个"故意让规则失效"的变异体 + 能变红的用例 | 变异体全部 SEALED |
| 看不见答案 | 把结论里的正确原因替换成错误原因 | 护栏判定**不变**（它只看证据） |

零成本是设计的一部分：复用 D19 的重放机制，任何人克隆后都能自己复现这两侧。

## 七、拓展阶梯

| 阶段 | 内容 | 关键验收 |
|---|---|---|
| **M1** | 判定核心（纯函数）+ 自家 reference adapter + `scripts/guard_replay.py` 零成本双侧验证 + 变异体 | 坏轨迹必须触发 / 好轨迹零误伤 |
| **M2** | 软层：LLM 审查者（一次自我修正，不进判分）+ **开关护栏的 2×2 对照** | 量化收益与误伤；测出负结论就如实报 |
| **M3** | **MCP 代理**落地 + 第二个适配器：一个**注入已知错误**的外部 Agent | 同一套规则在外部 Agent 上生效；错误由我们注入 ⇒ 有 ground truth |
| **M4** | `deny` 真正阻断工具调用；与 `policy/` 策略点合流；自动修复闭环（提案→人审批→执行→验证） | 越界动作被拦且留审计；修复后可验证（走隔离区可还原，不引入不可逆） |

## 八、明确**不做**的（边界，写在最前面避免误解）

- **不做"万能审查者"**：抓不到"结论方向反了"这类判断错误，也不打算抓（ADR-0007 决定 1）。
- **不让护栏参与评分**：它是运行路径的组件；一旦它影响 `correct`，
  评测就不再是"两侧同驱动的可比实验"。
- **不做"防止一切犯错"**：只拦**可判定的形式缺陷**；"看起来不对的思路"不拦。
- **不做实时流式干预**（M1–M3）：护栏在**步骤边界**上判定，不做逐 token 的干预。

## 十、M1 落地状态（**实测**，2026-09-25）

代码：`src/rca/guard/`（events / rules / verdict / adapters）+ `scripts/guard_replay.py`
用例：`tests/test_guard.py`（12 条）· 变异组：`guard_form_defects`（5 个，全部 SEALED）
完整经过见 `docs/harness-log.md` #55。

### 怎么自己验（零 API 成本）

```bash
python scripts/guard_replay.py --run runs/_eval/multi-20260925-131953   # 双侧对照表
python scripts/guard_replay.py --attempt F4:3                            # 单次明细 + 证据指针
python scripts/guard_replay.py --inject both                             # 注入形式缺陷（必须触发）
```

### 上线的两条规则（21 次真实尝试 **0 误伤**）

| 规则 | 抓到什么 | 实测 |
|---|---|---|
| `unsupported_claim` | 结论点名了一个轨迹里根本不存在的指标名/参数名 | 干净轨迹 0 报；注入后必报 |
| `unverifiable_number` | 测量数字既找不到、也算不出来（含舍入与单位换算的宽容） | 同上 |

### 被**降级**的那条（这条比上线的两条更值钱）

`unbased_metric`（"被当作根因的指标必须有参照"）本来是冲着 #44 那个真缺陷设计的。
实测：它抓到了 F4 的真缺陷，但 **19 个正确结论里报了 14 个**（F8 的泄漏是真故障，
只是指标只有一个采样值）⇒ **精确率 1/15 ≈ 7%，降级为诊断量**（`DIAGNOSTIC_RULES`）。

为什么修不好：区分"该不该拿这个指标当主根因"是**配权判断**，需要知道哪个原因才是真的
= 需要标准答案 = 超出护栏的表达力。**这是 ADR-0007 决定 1 的测量版证明。**

### 第一版被实测打回来的样子（留档，别重犯）

```
坏答案 2 次，护栏报出 0 次      ← 一条真缺陷都没抓到
好答案 19 次，护栏报出 7 次     ← 误伤
```

三个根因都是我规则写错：三个 **SKU** 被当成"基线"（漏报）、日志级别 `ERROR`
被当成指标名（误伤）、模型四舍五入的 `3.2` 与单位换算没处理（误伤）。

### 明确还没做到的

- **M1 只判定、不拦截**：`block` 是一句结论，不是一次阻断（真正阻断是 M4）；
- **抓不到配权类错误**：F4 那两次真坏答案它一次也没抓到 —— 这不是 bug，是边界；
- 日志级别那条不变量是**双机制冗余**，没有单点变异体能打红它（如实标注，不硬凑）。

## 十一、M2 软提醒：做到哪了（2026-09-25）

代码：`src/rca/agents/reviewer.py` + `coordinator.diagnose_multi(guard=…)` + `eval/runner.py --guard`
用例：`tests/test_reviewer.py`（8 条，全离线）· 变异组：`guard_soft_review`（4 个，全部 SEALED）

### 机制（已封堵）

| 不变量 | 为什么 |
|---|---|
| **fail-safe** | 新增的 LLM 调用路径坏掉**不能**作废整轮 —— 三个专员 + 质证 + 裁决的钱已经花掉（#15 的教训） |
| **"没审成" ≠ "没问题"** | 解析失败/异常必须留 `error`，不能悄悄返回空意见（#26 的空绿） |
| **最多 3 条意见、只修正一次** | 不迭代：第二次起就是自己说服自己；成本也失控 |
| **不进判分** | 审查意见只以"附在同一条 user 消息后的后缀"进入裁决，`correct` 只看结论文本 |

**冒烟实测**（F4 一次尝试，¥0.09）：`ran=True`、**提出 3 条意见**、**修订 1 次**、
护栏成本 ¥0.0154（约 **+17%**）。它提的不是套话 —— 例如"payment 失败 2153 与 inventory 失败 127
（17:1 放大）自相矛盾"、"同一事实被重复计数"。

### 2×2 实测结果（2026-09-26）

| | 臂 A 护栏关 | 臂 B 护栏开 |
|---|---|---|
| 尝试 | 21 | 21 |
| 答对 | **20/21 = 95.2%** | **21/21 = 100%** |
| 成本 | ¥1.5172 | ¥1.7739（**+16.9%**） |
| 审查触发 / 修订 | — | 21/21 / 21 |
| **修订帮了 / 帮了倒忙** | — | **1 / 0** |

**怎么读**（三条口径，缺一条就会读错）：

1. **臂间差异不能算"更准"** —— 差 1 格，而两臂是**非配对**样本、3 轮测不出幅度
   （D15 同配置自己就从 86% 抖到 100%）。只能说"没有变差"。
2. **真正的证据是那条配对记录**：`revision_helped=1 / revision_hurt=0`
   —— 同一次尝试内部的前后对照。软提醒**能把错的改对**，且 21 次里**0 次把对的改错**。
3. 判定用的是关键词判据，裁判口径未跑。

抽样读原文确认**审查者不是凑数**：它抓到"用已被撤回的断言支撑结论"、
"把观测缺失说成已证否"、"反事实断言无干预证据"这类真问题。

⇒ **结论：不做坏事、偶有正收益、代价 +16.9%；收益是否值这个价钱，3 轮答不了。**
定位是**可选能力，默认关闭**（`--guard`）。完整记录见 `docs/harness-log.md` #56。

### 顺带修掉一个真缺陷（这次事故暴露的）

崩溃会把**已经花钱跑完**的尝试一起丢掉：`run()` 抛异常时 `main()` 根本走不到存档那一步。
一个真实场景是"跑完 20 次、第 21 次撞上 402" ⇒ 20 次的钱和结果全没。

修法：单次尝试失败**跳过并继续**；401/402/403 判定为**致命**（立刻停，但把已完成的尝试留在
report 里，并写 `report.aborted_reason`）；其余当作抖动。用例 `tests/test_runner_resilience.py`（7 条），
变异组 `runner_survives_api_errors`（3 个，其中一个**故意重演原始事故**：abort 时清空已完成的尝试）。
