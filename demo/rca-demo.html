RCA-Agent · 公开实例

用确定性机制约束 LLM 的判断与行动 —— 一个把「测量本身可信」当成第一目标的故障根因分析实验。

本页由存档生成（scripts/make_demo.py），不是截图 —— 而存档与录制也随仓库提交（runs/_eval/）， 所以重跑一次生成器就能把这一页**逐字节复现**出来：不需要 API key，不花一分钱。

一、一句话结论

多 Agent 没有可测的价值增量。 在同一个世界里，单 Agent 用 ¥0.0172/次拿到 100% 准确率； 三专员 + 交叉质证 + 裁决用 ¥0.0690/次 （4.0×）拿到 100% —— 准确率没有任何优势。

比这个负结果本身更重要的，是它是被测量出来的： 一路上有六七次得到过相反的结论，每一次都是「尺子」坏了（见第四节）。

三、一次真实诊断的完整轨迹

场景 F8（多故障叠加：外部风控变慢 + order 内存泄漏）， 第 1 轮。下面是原样存档的工具调用与返回 —— 页面不替它修饰任何东西。

最终裁决

payment→外部风控这一跳引入约 800ms 延迟（风控耗时 800.5ms / payment 总耗时 818ms），并沿调用链向上传播（inventory 899ms → order 1032ms），导致全链路纯延迟劣化、8049 笔请求全部成功但耗时显著升高；到窗口右边界仍未恢复。；order 服务存在约 4.22GB 的字节泄漏（leak_bytes_total=4.22e+09），仅 order 有此指标、无任何错误计数、无连接池压力、日志侧无任何足迹。这是一个与上述延迟无因果关联的独立问题，需单独处置。
