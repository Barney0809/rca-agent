# rca-agent

> **多 Agent 根因定位与不可逆操作边界**

一个多 Agent 系统：它既要能**可靠地判断**（从故障现象回溯到根因），也要能**安全地行动**（任何不可逆操作都必须经过独立于模型判断的确定性边界）。

---

## 核心命题

> **LLM 的"自觉"不可靠——所以要用确定性的工程机制，同时约束它的判断和它的行动。**

| | 不可靠的"自觉" | 确定性机制 |
|---|---|---|
| **判断面** | 单视角的确认偏误：先看到 CPU 飙升，就一路去找流量证据 | **信息隔离 + 强制交叉举证** |
| **行动面** | 模型自己"会小心" | **路径/动词校验 + 不可逆操作默认拒绝** |

具体到实现上，有两条设计值得单独说：

### 1. 交叉举证是协议层的硬约束，不是提示词里的一句话

工具结果产出 `evidence_id`，Agent 的假设必须引用它。于是协调者可以**机械地**执行举证责任：

- 假设未引用任何证据 → 直接驳回
- 假设引用的证据全在支持自己、没有一条能证伪他人 → 驳回，并要求补证

**把软约束做成硬约束**，见 [`docs/03-事件流协议.md`](docs/03-事件流协议.md)。

### 2. 不存在硬删除

删除操作不直接删文件，而是**移入隔离区并设置 TTL**，可还原。

> 这一条来自一次真实事故：误删之所以无法挽回，**根因不是守卫没拦住，而是物理层面根本没有留下退路**——`-Force` 绕过了回收站，磁盘又没有卷影副本。
>
> 所以正解不是"守住不可逆操作"，而是**把不可逆变成可逆**。

---

## 这个项目是什么 / 不是什么

**是**：一个可复现的多 Agent 系统，带完整的评测集、留出集、对照 baseline、成本曲线与错误封堵清单。

**不是**：一个"让 AI 不再犯错"的承诺。任何守卫都可能被绕过——本项目交付的是**机制**，不是**保证**。

---

## 架构

```
Agent 层（LangGraph）   Coordinator + 三个专职 Agent（工具面隔离）
        │  MCP
策略执行点（独立进程）   路径规范化 · 动词分级 · 隔离区 · 审计
        │  只读遥测
遥测层                 接入 → 降维（原始遥测永不进入上下文）
        │
被诊断世界              order → inventory → payment（自建、开源、可注入故障）
```

详见 [`docs/02-技术方案与排期.md`](docs/02-技术方案与排期.md)。
